# v1.6.2（2026-08-26）OpenCASCADE 8.0.1 接入与双生成器适配

> 本版本以 CMake `project(... VERSION 1.6.2)` 为单一版本源，应用、模块信息和工程包 fallback 同步使用该版本。

## 交付范围

- 将项目 OpenCASCADE 依赖从 7.9.0 升级到 `J:/Develop/OCC8.0.1` 中的 8.0.1 Debug/Release 合并包。
- 适配 OCCT 8 删除的 AIS 列表别名及二维向量类型，保持 CAD 导入网格并行开启。
- 更新 Debug/Release OCCT、TBB、Coal、Qt 和相关第三方运行库快照，按配置部署实际链接闭包。
- 修复 Visual Studio 生成树保留旧 OCCT 7.9 缓存导致 `find_package(OpenCASCADE 8.0.1 EXACT)` 失败的问题。
- 扩展 CAD 脱离式导入测试，使其可显式传入外部 STEP 文件进行原链路回归。

## 主要实现

1. CMake 固定要求 OpenCASCADE 8.0.1，并把 OCCT、zlib、第三方库和 TBB 根目录统一切换到 `J:/Develop/OCC8.0.1/occt-combined-with-debug-pch`。
2. 公共 preset 显式传递上述依赖路径，使已有 `build-cmake/` 和 `build-vs/` 缓存也能确定性切换版本；两种生成器继续使用独立生成树和 `x64/ninja/<Config>`、`x64/vs/<Config>` 输出。
3. `GuiDocument`、`RenderingManager` 和 `WidgetOccView` 使用 `NCollection_List` 与 `NCollection_Vec2<int>` 替代 OCCT 8 已移除的类型。
4. 由 CMake 生成 `LaserCNC` 实际运行 DLL 清单；运行库刷新脚本只镜像当前 OCCT 闭包，并按 Debug/Release 部署对应 TBB，清理另一配置的残留 DLL。
5. 测试运行库改为集中部署，避免并行构建多个测试目标时同时复制相同 DLL 造成竞争。
6. `lcnc_cad_detached_import_test` 保留默认小模型回归，并支持命令行传入外部 STEP；生产代码中的 `BRepMesh_IncrementalMesh` 继续设置 `InParallel = true`。

## 验证证据

- `cmake --preset acs-gtn` 与 `cmake --preset vs-acs-gtn` 均识别 OpenCASCADE 8.0.1。
- Ninja ACS+GTN Debug 全量构建通过；最终 Debug CTest 41/41 通过，总耗时 430.20 秒。
- Ninja Release `LaserCNC` 目标构建通过；最终架构、CAD 脱离式导入和启动冒烟复核 3/3 通过。
- VS/MSBuild Debug 全量构建通过；架构、CAD 脱离式导入和启动冒烟 3/3 通过。
- VS/MSBuild Release `LaserCNC` 目标构建通过，`LaserCNC.exe --smoke-test` 退出码为 0。
- Ninja 与 VS 输出中的 Debug/Release `TKernel.dll`、`TKMesh.dll` SHA-256 均与对应 OCCT 8.0.1 源包一致。
- Debug 输出仅包含 `tbb12_debug.dll`、`tbbmalloc_debug.dll`；Release 输出仅包含 `tbb12.dll`、`tbbmalloc.dll`。
- `git diff --check`、PowerShell 运行库刷新脚本语法检查和架构门禁通过。

## 大型 STEP 回归边界

- 42.7 MB 目标 STEP 通过实际 CAD 异步导入与并行网格链路运行，越过旧版本约 84 秒的栈溢出点，未再复现该栈溢出。
- 外部模型测试在 300 秒超时前未完成；OCCT 工作仍继续占用 CPU，峰值工作集约 9.6 GB，超时后不能及时协作取消，约 14 分钟后人工终止该测试进程。
- 因此本版本证明了 OCCT 8.0.1 的构建、运行库及常规回归可用，但不能宣称该大型模型导入性能、资源占用和取消行为已经验收通过。

## 未放行项

- OCCT 8 对 `TDF_LabelSequence`、`TopTools_*`、`Standard_Real`、`Standard_True/False`、`GetMessageString()` 等旧 API 产生较多弃用警告；普通构建通过，但尚未完成 `/WX` 质量配置的全量迁移。
- 未执行本补丁的 ASan、长时间资源趋势或 Application Verifier；Application Verifier 仍需单独授权和交互环境。
- 未完成人工 GUI 文件打开、三维显示交互和大型 STEP 完整导入验收。
- 未执行物理 ACS/GTN、激光、IO 或真实机床加工验证；自动化、SDK 仿真、GUI 和物理机证据互不替代。
