# LaserCNC 双构建路线隔离修复

**版本**：v1.2.1
**日期**：2026-07-30
**状态**：CMake/Ninja 与 Visual Studio/MSBuild Debug 构建及两套自动化测试通过。

## 修复内容

- 将 CMake/Ninja Multi-Config 生成树固定为 `build-cmake/`。
- 将 Visual Studio 2022/MSBuild 解决方案生成树固定为 `build-vs/`。
- 新增 `vs-acs-gtn`、`vs-acs-gtn-debug` 和
  `vs-acs-gtn-release` presets。
- CMake 明确拒绝继续使用曾被两种生成器共用的旧 `build/`。
- 应用与运行依赖的唯一输出固定为根目录 `x64/Debug/` 或
  `x64/Release/`，不再允许通过 CMake cache 改写。
- 新增 `BUILD.md` 作为构建流程权威文档，并同步 `AGENTS.md`、
  `CLAUDE.md`、README、VS Code 任务、审计和交付文档。
- 改进旧构建树清理脚本：遇到 IDE 占用文件时继续清理其他生成产物，并
  明确报告被锁定的剩余缓存。

## 问题根因

旧 Visual Studio 解决方案与 Ninja preset 共用了 `build/`。解决方案缓存
仍引用已删除的死代码，同时混入不同 MSVC 工具集生成的对象，造成 C1083、
MSB8064/MSB8065、LNK4098、LNK2019 和 LNK1120。

本版本不恢复这些死代码，而是从生成树边界消除缓存和工具链交叉污染。

## 验证边界

- 本轮验证为 ACS+GTN Debug 软件构建与自动化测试，不代表 ACS/GTN 真机验证。
- 未验证 Release、all-off、ACS-only、GTN-only、real-laser 和 ASan 矩阵。
- 旧 `build/` 只剩被当前 Visual Studio 进程锁定的 `.vs/Copilot` 缓存；
  关闭旧解决方案后运行
  `scripts/clean_legacy_build_artifacts.ps1 -Execute` 即可移除。
