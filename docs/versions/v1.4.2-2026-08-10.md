# LaserCNC v1.4.2 — Process 构建环境与类型边界整理

日期：2026-08-10

## 交付范围

- 新增 `lcnc_msvc_environment` CMake 接口目标：从已配置的 MSVC/Windows SDK 工具链推导标准库、SDK 头文件和链接目录，并传播到公共依赖、源码构建的 QuaZip 及独立测试目标。
- CMake Tools 直接启动 Ninja 时不再依赖 `VsDevCmd` 注入的 `INCLUDE`/`LIB`；配置阶段会校验推导出的关键头文件和库文件，缺失时明确失败。
- 删除旧的 `process/system/data_type.h` 聚合头，拆分为命名空间化的轴、权限、设备 IO 和数值常量头文件。
- 删除未使用的旧工作流状态和全局宏/`using` 泄漏；Process 设备控制、运行时服务、工作流与测试改为显式包含和限定名。
- 保持 Process 的设备访问、停止语义和 ACS/GTN/SimulatorCMHP 控制逻辑不变；此次仅调整构建依赖和类型可见性。

## 已实现验证

- `cmake --preset acs-gtn` 配置通过。
- 在子进程清空 `INCLUDE` 和 `LIB` 后，执行 `cmake --build --preset acs-gtn-debug --target lcnc_process_runtime_configuration_test --clean-first --parallel 16` 成功；该目标可直接包含标准库头 `<map>` 并链接。
- `cmake --build --preset acs-gtn-debug --parallel 16` 成功，重新生成并链接 `x64/Debug/LaserCNC.exe`。
- `ctest --test-dir build-cmake --build-config Debug --output-on-failure` 26/26 通过，包含架构门禁、运行时配置、手动运动、工作流、SimulatorCMHP 和启动冒烟。
- `git diff --check` 通过；确认无旧 `data_type.h`、废弃工作流类型或 Process OCC 依赖残留。

## 验证边界与后续事项

- SimulatorCMHP 仅证明 ACS SDK 模拟器的连接、加载和基本运动路径可用，不等同于真实 ACS/GTN 控制器、激光器、急停链路或长期运行验证。
- 本次未改变设备队列、停止恢复、轴配置或运动插补策略；真实机台仍应按既有安全流程完成回零、IO、限位和加工验收。
- `.claude/` 与 `_build_inc.bat` 是本地开发辅助文件，未纳入本次交付。
