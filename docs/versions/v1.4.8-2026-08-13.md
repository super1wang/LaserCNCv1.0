# v1.4.8 - 2026-08-13

## 基于工件表面的五轴空程轨迹

- 轮廓间空程由 CAM 在生成加工顺序时一次性完成：构造加工面侧的近似曲线，按工件最高障碍和切割嘴保守径向包络计算安全抬高量，再把上一轮廓末点、空程采样、下一轮廓引入点及轮廓点连续求解为完整五轴位姿。
- 球面优先生成端点之间的短大圆弧；普通曲面使用有界三次曲线。执行轨迹被约束为一次抬升、少量协调直线/曲线采样和一次下降，不进行逐点实体精确距离计算。
- 应用程序选项支持模拟锥头或 STEP/STL/BREP 轻量切割嘴代理；修改参数并应用后立即刷新 View、使执行缓存失效并重新生成当前顺序。STEP 读取支持中文 UTF-8 路径，并以实际传输形体判断有效性。
- 原始、未求解的几何曲线以固定 5 mm 示意偏置构造成 OCC Edge，并在顶层以虚线显示；显示开关只读取已生成缓存，工件安装或转台姿态刷新时继续跟随工件变换。
- Process 只消费 OCC-free 的已求解空程段。ACS/GTN 以与切割相同的协调插补格式执行空程，激光保持关闭，空程完成后再构建并启动切割段；工具切割高度和空程高度仅在指令构建阶段叠加。
- 部分加工只复用与请求子顺序相邻关系一致的已验证空程。多个轮廓缺失、失败或过期的空程计划会成为加工硬失败；单轮廓加工不要求轮廓间空程。
- 无工件或切割嘴碰撞几何时规划失败；OpenCASCADE 网格、球面识别和包围盒异常被收敛为失败结果，避免从生成刀路调用链泄漏异常。

## 配置与构建稳定性

- `TomlConfig` 通过 `QFile` 读取配置字节后交给 toml11 内存流解析，避免 Windows 中文路径和启动配置文件句柄异常导致模块构造崩溃。
- Ninja/MSVC 构建固定 `VSLANG=1033`，并修正本地化 `/showIncludes` 前缀，防止公共头修改后依赖对象未重编而形成 ABI 混编。
- CAM 图层采用一次规范化入口分配轮廓 ID，避免重复扫描；空程派生数据不写入 `.lcnc`。

## 审查修正

- 删除早期方案遗留、但当前空程算法未消费的 `leadOut` 求解。该位姿曾被错误作为下一轮廓 IK 的连续性前态，可能使生成结果与轮廓实际结束位姿不一致。
- 后台线程导出部分加工子顺序时保留并裁剪已验证空程，不再返回缺少空程的普通刀路快照。
- 加强代理模式输入校验、异常边界和新增用户可见消息的中文翻译。

## 尚未验证和发布限制

- 加载机台模型后的真实切割头、机架、转台、夹具和工件碰撞分支尚未进行 GUI、样件或真机验证，不得据此认定机台环境规划已满足生产安全要求。
- 当前机台环境只校验已求解采样点，尚未完成连续扫掠、碰撞后的候选路径重规划、显式忽略碰撞对和配置化真实头部间隙。具体问题与下一步验收项记录在 `todo.md`。
- SimulatorCMHP 只能作为 SDK 与指令链证据；生产验收仍需无激光、低速真机验证安装误差、最小间隙及 ACS/GTN 同步运动。
