# LaserCNC v1.5.8（2026-08-21）

## 交付范围

- 对 CAM 模块执行文件级功能、边界和架构审查，将 `cam_module.cpp` 从 10686 行缩减到 466 行，仅保留模块生命周期、服务注册、工作区绑定和基础配置职责。
- 按刀路、碰撞检测、加工流水线、机床模型、显示、交互、集成和内部辅助拆分 `CamModule` 实现，并将公共跨模块接口统一归入 `contracts/`。
- 将 CAM 命令和 UI 继续按刀路、机床、碰撞及 Ribbon 分类；将 `commands_cam`、`commands_machine`、`cam_module_internal` 分别规范为 `toolpath_commands`、`machine_commands`、`cam_module_support`。
- 新增刀路顺序/修订投影、事务求解、碰撞几何缓存、切割头碰撞几何及跨模块服务适配器，删除同步旧流水线、无消费者接口和重复配置影子状态。
- 修复有序刀路求解失败时提前修改已提交轮廓和机床坐标的问题；求解现针对副本执行，并仅在全量成功后提交。
- 补齐执行修订号对切割/快速偏移、刀具映射、轮廓几何与流水线完整状态的覆盖，避免错误复用旧运动计划或碰撞快照。
- 收紧机床模型导入导出的异常边界，统一记录 OCC、标准及未知异常，并向界面报告具体失败原因及中文翻译。
- 新增 `src/modules/cam/README.md`，记录目录职责和 Process-facing OCC-free 不可变快照约束。

## 审阅结论

- 已检查全部已跟踪修改、删除项和未跟踪文件；所有内容均属于本次 CAM 审查、拆分、目录迁移、回归测试及对应引用更新，没有发现构建产物、本地配置或无关辅助文件。
- `CamModule` 入口不再承载刀路、碰撞、流水线、机床和显示的具体实现；公共契约、Kernel 集成和私有辅助代码的目录边界已分离。
- Process 和 Simulation 的修改仅为 CAM 公共契约迁移后的 include 路径更新；Process 仍不包含 OCC 类型，也未获得刀路重排或求解能力。
- 刀路有序求解与手动/自动顺序提交保持事务语义；求解失败不会破坏上一个已提交刀路。
- CAM 修订号包含执行、显示及安全快照相关输入，机床加载和流水线不完整状态会使旧运动计划失效。
- 现有类名符合 PascalCase 规范，未进行只增加 Qt MOC、翻译上下文和外部调用风险的无收益类名修改。
