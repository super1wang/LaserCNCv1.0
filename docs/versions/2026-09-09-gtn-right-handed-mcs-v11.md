# 2026-09-09 GTN 五轴模型 MCS 坐标基修复（v11）

## 结论与证据

供应商指出的 `axisVector[4][2] = -1` 可以由当前代码确定复现，但不能仅凭该参数断言已证明现场规划/编码器反向的全部原因。

旧 `buildControllerKinematicsSnapshot()` 用 `worldToAxisCoordinates()` 同时投影直线与旋转轴方向，再交给 `GTN_SetGroupKinematicTransform()`。对于 X=世界 +X、Y=世界 +Y、Z=世界 -Z、C=世界 +Z 的构型，该投影把 Z 方向变成 +Z、C 方向变成 -Z。与此同时，CAM 的 `tcpMcsX/Y/Z` 来自机床世界坐标中的运动节点，空程 TCP 也来自同一世界系。模型与 TCP 使用了不同坐标基。

本地供应商资料《新架构功能编程手册(20231115)》第 10.2.4 节、PDF 第 146 页规定：`dirMode=1` 时 `axisVector` 是相对 MCS 的单位向量；`dir[0..2]` 表示工具侧/工件侧，后两项必须为 0。不能通过 `dir[4]` 再做 C 轴补偿。资料中的正交模式刀具侧方向说明也不能直接替代非正交模式的单位向量配置。

## 修复边界

- GTN MCS 明确定义为与 CAM TCP 一致的 **Z 向上、右手机床世界系**，不是控制器各轴正方向拼成的轴值坐标基。
- 五个轴方向保留配置中的世界方向并单位化；真实负向、斜向旋转轴仍保留，未做取绝对值或按轴名固定符号。
- 旋转中心在配置中仍以轴坐标编辑/持久化，仅在进入 GTN 快照时转换到世界 MCS；轴反馈、输入/显示、当量、CAM 软件 IK 轴值均不改。
- 标定记录升级为 schema 2：MCS 点和向量统一采用世界系。激活时只把中心转回配置轴坐标，方向不再二次转换。
- schema 1 记录保留可读和哈希校验，但拒绝新建、激活及作为活动 Group 参数使用。不自动覆盖历史记录、不继承旧物理验收资格。
- 标定界面增加坐标含义说明；初始化日志逐轴输出 `mcs=MachineWorldZUpV2`、物理轴号、方向及中心，适配器版本为 `right-handed-machine-mcs-v11`。
- C 轴规划/反馈故障锁存、首错证据、停止确认、取消后禁止 Start 等保护保持不变；未修改硬件编码器反向位、未清除现场故障或发起运动。

以测试构型为例：

| 参数 | 旧快照 | 修正后 |
| --- | --- | --- |
| Z 轴向量（配置世界 -Z） | `(0,0,+1)` | `(0,0,-1)` |
| B 轴向量（配置世界 +Y） | `(0,+1,0)` | `(0,+1,0)` |
| C 轴向量（配置世界 +Z） | `(0,0,-1)` | `(0,0,+1)` |
| 中心：配置轴坐标 `(290,40,30)` | `(290,40,30)` | 世界 MCS `(290,40,-30)` |

以上只是此方向配置下的转换，不是对所有机型硬编码上述数值。`dirMode` 仍为 1，物理轴号/比例不变。

## 更新后的操作要求

1. 完全停止并使用新程序重新连接，确认初始化日志版本为 v11。
2. 如果存在旧活动标定，使用“从当前构型生成 RTCP 试运动参数”重新生成 schema 2；物理标定则需在明确的新 MCS 定义下重新测量/核验。MCS 输入不能直接照抄可能左手的轴反馈坐标，尤其 Z 向下为正时。
3. 复核世界系旋转中心、零位 TCP、五轴向量和物理轴号。旧文件保留作证据。
4. 由具备现场权限的操作员在激光关闭、低速、无干涉且急停可用条件下，分别验证轴坐标运动及 RTCP 开/关的正负小角度、规划/编码器反馈和固定 TCP。任何反向或偏差继续故障停机，不绕过保护。
