# 修复开新文件后工件模型未更新到当前轴系姿态

**版本**：v1.3.29

**日期**：2026-08-04

**状态**：修复关闭文件、打开新文件后（旋转轴处于非零位时），工件模型停在零位/旧姿态、与机台当前姿态不重合，手动添加的加工面高亮（位置正确）相对工件"错位"，只有轴运动后才跟随更新的问题。

## 本次交付范围

- 根因：`MainWindow::onProjectDomainChanged`（Workpiece 域）里 `autoInstallCurrentWorkpiece()` 会挂载工件并刷新变换，但该刷新发生在 `activateWorkspaceOccView` 把 OCC 视图挂接到本文档**之前**。此时视图尚未就绪，`updateMachineWorkspaceTransforms` 的 `SetLocalTransformation` + `RecomputePrsOnly` 对工件 AIS 不生效，工件 AIS 停在 rebuildDomain 时的恒等（零位）姿态，直到下一次轴运动 tick（`refreshMachineTransforms`）才被纠正。加工面高亮由 v1.3.27 在创建时即施加 `computeWpcTransform`，位置正确，故表现为"加工面高亮对、工件错位"。
- 修复：在 `activateWorkspaceOccView` 之后追加一次 `CamModule::refreshMachineTransforms()`，复刻轴运动 tick 的路径（`updateMachineWorkspaceTransforms` + `updateMachiningFaceTransforms` + 重绘），在视图就绪后立即把当前运动学姿态重新施加到工件 AIS 及加工面高亮上。`refreshMachineTransforms` 已是 public，内部 `Redraw` 由 `gd->hasView()` 守护，无视图时安全。
- 经用户验证：开新文件（旋转轴非零位）后，工件模型立即处于当前姿态，加工面高亮与工件重合，无需等待轴运动。
