# v1.4.7 — 2026-08-12

## 构建与运行目录隔离

- CMake/Ninja Debug 与 Release 运行产物分别部署到 `x64/ninja/Debug/` 和
  `x64/ninja/Release/`；Visual Studio/MSBuild 则部署到 `x64/vs/Debug/` 和
  `x64/vs/Release/`。
- `asan` 与 `all-off` 进一步部署到 `x64/ninja-asan/<Config>/` 和
  `x64/ninja-all-off/<Config>/`；其它硬件/质量 Ninja preset 也使用各自的
  `x64/ninja-<variant>/<Config>/` 目录。
- `LaserCNC.exe`、Qt/OCC/SDK DLL、`Simulator.prg`、运行配置及 `lcnc_project_upgrade`
  均跟随同一生成器目录，避免 VS 调试会话和 Ninja 部署互相覆盖或锁定文件。
- VS Code F5 与运行时基准脚本默认使用 `x64/ninja/Debug/`；基准脚本可通过
  `-Executable x64\\vs\\Debug\\LaserCNC.exe` 显式测试 VS 版本。

## Visual Studio 自动重配置

- 当 Visual Studio 缓存 `CMAKE_RC_COMPILER=rc` 且没有继承 `WindowsSdkDir` 时，CMake
  先从 PATH 解析 `rc.exe`；若不可用，再从 Windows Kits 注册表选择一个完整的 SDK。
- 这消除了 `Unable to derive the Windows SDK root` 导致的 `ZERO_CHECK` 与后续
  `MSB8066` 连锁失败。

- Ninja 与 ASan 的启动冒烟受本机 Sogou 输入法注入阻塞：ASan 报告的 use-after-free
  仅含 `SogouPY.ime` / `SogouTSF.ime`、Windows 和 Qt 帧，项目代码仅处于 Qt 事件循环
  入口。关闭/卸载该输入法或禁用其 TSF 注入后，应重新执行两条启动冒烟测试；当前不能把
  此项判定为项目代码已通过。
