# LaserCNC 模块任务生命周期骨架

**版本**：v1.3.2

**日期**：2026-08-03

**状态**：源码审阅、ACS+GTN Debug 构建和定向自动化测试通过；这是入口瘦身的
共用基础阶段，不替代后续 Process/CAM/CAD/MainWindow 拆分或物理硬件验证。

## 本次交付范围

- 新增 `lcnc::ModuleTaskScope`，作为模块私有的任务所有权容器，集中处理任务
  跟踪、终态释放、协作取消和有限时间等待。
- `CadModule`、`CamModule`、`ProcessModule` 统一改用该作用域，删除各自重复的
  `QSet<TaskId>` 和跟踪/释放辅助实现。
- 模块原有停止路径和超时决策保持不变；该基础设施不新增后台线程、不改变任务
  调度器语义，也不访问设备 SDK。
- 新增执行进度文档，明确本阶段已完成以及后续四个入口下沉阶段仍未完成。

## 验证证据

- `cmake --build --preset acs-gtn-debug --parallel 16`：成功，包含核心库、三个模块
  和 `x64/Debug/LaserCNC.exe` 链接。
- `ctest --test-dir build-cmake --build-config Debug --output-on-failure -R
  "lcnc_task_manager_test|lcnc_process_run_coordinator_test|lcnc_process_current_schema_test|lcnc_startup_smoke_test"`：4/4 通过。
- `lcnc_task_manager_test` 增加 `ModuleTaskScope` 协作取消、等待和终态释放覆盖。
- `git diff --check`：通过。

## 未完成与验证边界

- 该阶段尚未引入 `ProcessDeviceExecutor`，runtime 外的设备锁和原始设备访问仍待
  Process 阶段统一迁移。
- 尚未完成 CAM、CAD、MainWindow 的业务职责下沉，也尚未达到四个入口的行数门限。
- 未执行 ACS、GTN 或激光物理设备测试；`SimulatorCMHP` 后续 SDK 测试也不作为
  物理硬件验证。
