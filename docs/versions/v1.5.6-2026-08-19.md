# LaserCNC v1.5.6（2026-08-19）

## 交付范围

- 重构自动化测试分层，优先保留 CAM、运动学、碰撞、任务生命周期和 Process 安全等关键算法及流程门禁，并为 CTest 增加 `critical`、`algorithm`、`flow`、`safety`、`sdk-integration` 和 `support` 标签。
- 使用仓库真实 `model/半球.stp` 增加四个可独立定位的制造流程用例：通过 `LcncProjectManager` 打开工件、执行 CAM 五阶段流水线、验证无机台工件代理碰撞、验证机台模式碰撞状态对 Process 的禁止/放行契约。
- CAM 流程覆盖面分离、轮廓提取、点离散、几何刀路和 XYZ 机床坐标求解，并校验五阶段 revision 链完整。
- 加工流程测试覆盖默认 `Start -> NormalCutting -> Stop` 执行，同时保留流程持久化、Loop/If 和轴位置步骤契约。
- 合并碰撞扫描策略、运行状态机、异步 CAM 结果接收等近似小型用例；移除仅用于临时排障的引刀与圆锥构造诊断程序，CTest 从 36 项整理为 34 项。
- 修复测试复跑发现的 `TaskManager::requestAbort()` 终态竞态：取消线程不再把工作线程已经写入的 `Cancelled` 覆盖回非终态 `CancelRequested`。
- 新增 `tests/README.md`，记录测试标签、流程覆盖、维护原则以及 SimulatorCMHP/实体硬件证据边界。

## 审阅结论

- 已检查全部已跟踪修改、删除项和未跟踪文件；工作区只有本次测试重构、任务取消竞态修复、测试说明和本版本记录，没有发现无关代码、构建脚本、日志或本地配置文件。
- 被删除的六个测试源文件中，两个为无稳定业务成功条件的诊断程序，其余断言均已合并进相邻的 CAM、碰撞、Process 安全或工作流测试，没有直接丢弃关键回归覆盖。
- `TaskManager` 修复使用原子比较交换，仅允许 `Queued`/`Running` 进入 `CancelRequested`；已经到达 `Succeeded`、`Failed` 或 `Cancelled` 的任务不会被取消请求覆盖。
- Process 继续只消费 CAM 输出的无 OCC 快照；本次测试与生产代码没有向 Process 引入 OCC 类型、二次 IK 或轮廓重排。

## 验证证据

- `cmake --preset acs-gtn` 与 `cmake --build --preset acs-gtn-debug --parallel 16`：Ninja Debug 全量构建通过。
- `ctest --test-dir build-cmake --build-config Debug --output-on-failure`：最终 34/34 通过，总耗时约 56 秒，包含真实 STEP 流程、关键算法、安全门禁、SimulatorCMHP SDK 集成和启动烟雾测试。
- `ctest --test-dir build-cmake -R "^lcnc_task_manager_test$" --repeat until-fail:50`：任务取消回归连续 50 次通过。
- `cmake --preset asan` 与 `cmake --build --preset asan --parallel 16`：ASan 全量构建通过；任务、CAM 流水线、碰撞、Process 工作流等相关测试 9/9 通过。
- 架构门禁、遗留工作区 API 扫描、Process OCC 头文件边界扫描和 `git diff --check` 通过。

## 仍需验证

- 机台模式自动化当前验证 `FullEnvironment` 模式、碰撞状态传播和 Process fail-closed 契约；真实 AC/BC/摆头装配的全部碰撞对、连续扫掠、碰撞触发重规划和长时间性能仍需专门测试。
- SimulatorCMHP 结果只证明 ACS SDK 模拟器链路；实体 ACS/GTN 机台仍需执行低速无激光、夹具/限位/安全 IO 和急停恢复验收。
- 本次未进行 GUI 人工交互验收或长期资源趋势测试；自动化流程直接验证核心文件、算法和服务边界，不替代操作界面与生产现场确认。
