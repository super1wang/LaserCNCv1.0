# v1.6.3（2026-08-26）OpenCASCADE 8.0.1 深层适配与大型 STEP 加速

> 本版本以 CMake `project(... VERSION 1.6.3)` 为单一版本源，应用、模块信息和工程包 fallback 同步使用该版本。

## 交付范围

- 清理项目中仍由 OCCT 8.0.1 标记弃用的基础类型、容器别名、异常消息和曲面访问接口。
- 保留 `BRepMesh_IncrementalMesh` 并行执行，按精确 B-Rep 面数和模型尺度选择普通、复杂、超复杂三档显示网格参数。
- 将“打开文件”与“导入文件”统一到脱离式读取、后台网格化、文档线程事务提交链路，避免取消或失败留下半导入文档。
- 将 OCCT 进度范围接入 `TaskProgress`，使 STEP 传输和显示网格阶段可报告进度并协作取消；相同整数进度不再重复通知 Qt/UI。
- 按 OCCT 8 并发约束保留独立 STEP reader 并发，对仍使用进程级状态的 IGES reader 串行保护。

## OCCT 8.0.1 接口迁移

- `Standard_True/False`、`Standard_Integer/Real/ShortReal/Boolean` 改为原生 C++ 类型。
- `TDF_LabelSequence`、`TopTools_*`、`TColgp_*`、`TColStd_*`、`BRepOffset_ListOfInterval` 和旧灯光迭代器改为直接 `NCollection` 类型。
- `Standard_Failure::GetMessageString()` 改为 `what()`。
- 面法向计算改用 `GeomAdaptor_Surface::GeomSurfaceTransformed()`，正确包含面 Location 变换并消除旧曲面访问弃用警告。
- 最终源码和测试扫描未发现本轮覆盖的 OCCT 弃用符号；Debug、Release 编译未再出现 OCCT 弃用警告。

## 大型 STEP 根因与策略

- 目标 `飞秒综合一体机管板一体机2.STEP` 为约 42.7 MB、17,728 个面，随附诊断包含环边顶点吸附、回路完整性和曲面问题；对照 `精简ac转台.stp` 约 65.9 MB、12,526 个面。文件字节数不能代表网格成本，主要瓶颈是面数、曲率及异常几何共同放大原高精度显示网格开销。
- 8,000 面以上使用复杂显示档，14,000 面以上使用超复杂显示档；线性偏差按模型尺度限幅，角度分别放宽到 10°/15°。超复杂档关闭内部顶点和曲面偏差复检，避免仅用于显示的三角网格消耗数十分钟和多 GB 内存。
- 策略只清理并重建显示三角网格，不修改精确 B-Rep；CAM、碰撞和刀路算法仍按各自精度要求构造计算数据。
- 每个 profile 继续设置 `InParallel = true`，未以串行网格化规避问题。

## 最终验证证据

- Release 实际完整导入：目标 STEP 20,191 ms；对照 STEP 9,628 ms，均显著低于两分钟目标。
- Debug 目标 STEP 完整导入 110,291 ms，采样峰值工作集约 657 MB；不再出现旧版本超过 14 分钟、约 9.6 GB 的显示网格失控。
- Ninja ACS+GTN Debug 与 Release 全量构建通过。
- VS/MSBuild ACS+GTN Debug 全量构建、Release `LaserCNC` 目标构建通过；输出分别位于 `x64/vs/Debug`、`x64/vs/Release`。
- Debug CTest 41/41 通过，总耗时 419.21 秒。
- MSVC AddressSanitizer 全量构建通过；架构、任务取消、OCCT 精确操作锁、CAD 脱离式导入定向回归 4/4 通过。
- `git diff --check`、层依赖、Process 无 OCC include、旧工程 API 和 OCCT 弃用符号扫描通过。

## 交付边界

- 两份真实样本已达到目标，但不能对任意损坏、恶意构造或极端曲面密度的 100 MB STEP 作绝对两分钟保证。

- 未执行物理 ACS/GTN、激光、IO 或真实机床加工验证；自动化、SDK 仿真、GUI 和物理机证据互不替代。
