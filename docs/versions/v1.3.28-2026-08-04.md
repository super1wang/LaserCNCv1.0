# 修复小孔轮廓下刀点求解失败并容错单轮廓错误

**版本**：v1.3.28

**日期**：2026-08-04

**状态**：修复自由曲面（大加工面 + 大量小孔）上手选加工面后，下刀点大面积求解失败、整体生成耗时长的问题。

## 本次交付范围

### 1. 根因修复：小孔下刀点"两侧均落加工面"误判（`core/algorithms/cam/laser_toolpath.cpp`）

- 现象：对"半球/自由曲面上很多小孔"类零件，手动选面后提取出数百条孔轮廓，下刀点求解 ~99% 失败，错误统一为"下刀线两侧投影均落在加工外表面，无法确定悬空侧"，单次生成耗时 250 s 量级。
- 根因：`computeLeadInSolution` 沿起点切向两侧各探一根下刀线（最长 5 mm）判定悬空侧。当孔径小于下刀线长度时，朝孔内方向的采样点会穿过小孔、落在孔对侧的加工面上，导致正反两侧都判为"落在加工面"。原代码在"两侧均落面"时**直接报错返回**，发生在横截面法向 / 实体分类兜底逻辑**之前**——即便相邻孔壁法向能明确指向孔内空腔（悬空侧），也从未被调用。
- 修复：删除"两侧均落面即提前返回"的分支，使其继续向下走横截面法向 + 实体分类兜底，由孔壁法向判定悬空侧。
- 实测（诊断程序 `lcnc_cam_lead_in_diag` 跑用户零件 `支架-成品图(1).STEP`，6 个外面 + 842 个 B 样条孔壁）：
  - 只选外表面：844 条轮廓，修复前 14 成功 / 830 失败 / 255 s → 修复后 **844 成功 / 0 失败 / 14 s**。
  - 外表面+横截面（tube）：842 条轮廓，修复前 5 成功 / 837 失败 / 253 s → 修复后 **842 成功 / 0 失败 / 14 s**。
  - 结论：成功率 ~1% → 100%，速度提升约 18 倍（成功在首个候选点即解出，不再遍历全部候选）；且**横截面是否手选不再影响成功率**（孔壁法向由 `bindOwnedWireSurfaceContext` 经边邻接自动发现）。

### 2. 容错：单轮廓下刀点失败不再中止整体生成（`modules/cam/cam_module.*`、`app/main_window.cpp`）

- 之前任一轮廓下刀点计算失败即 `return` 中止整条刀路生成。改为：失败轮廓保留（置 `leadInSolution.valid=false` 并记录错误原因）、不添加下刀点、继续后续轮廓；生成完成后对新增的 `operationWarning` 信号弹一次黄色警告框列出失败轮廓名与原因。
- 四条批量生成路径（`generateToolpath` / `generateToolpathAsync` / `buildCurrentGeometricToolpath` / `buildCurrentGeometricToolpathAsync`）一致处理；异步全局生成里的 `coordinatesValid` 校验放宽为"无下刀点的轮廓可接受，仅采样点 IK 失败才算硬失败"。
- 保留轮廓经导出快照带 `hasLeadIn=false` + 具体原因，Process 会在该轮廓上报错拒加工，不会误加工；渲染器与空程路径均已天然兼容无下刀点轮廓。单轮廓人工操作（设置下刀点、重算当前轮廓）仍保持严格校验。
- 该容错现为兜底——经第 1 项根因修复后，小孔轮廓基本不再失败。

### 3. 诊断工具（`tests/cam_lead_in_diag.cpp`、`CMakeLists.txt`）

- 新增 `lcnc_cam_lead_in_diag` 目标（手动运行，不在 ctest 内）：加载 STEP，对每种提取策略 + 手选面组合跑"提取轮廓 + 下刀点求解"，输出每条轮廓的成功/失败/原因/耗时与错误直方图。用于后续下刀点算法调优的快速复现。
