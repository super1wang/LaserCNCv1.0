## 1. 修复内容

| 审阅项 | 本次处理 |
| --- | --- |
| 构建指令、DataEnd 期间收到停止仍可能启动 | 空程和切割逐点检查停止；DataEnd 前后、启动前诊断后再检查；已取消则不调用 StartCommandList。 |

厂商 Start 调用一旦已经进入，软件不能抢占。此时记录实际返回结果，保留停止请求，由设备线程继续执行排队的停机，不能宣称“从未启动”。

## 2. 停止、清理与恢复约束

- `GTN_GroupStop` 不作为运行中 CommandList 的替代停止指令；列表处于 Delay/IO 等待时，即使 Group.run 为零也检查 list.execute。
- 停稳确认必须同时有有效状态读数。读失败立即失败；运动未结束时轮询最多 30 秒。该期限不能中断已经进入且不返回的厂商函数。
- 请求和确认均成功后才执行 Disable → Ungroup → ClearListData → ClearListStatus；任何一步失败停止清理链。
- 部分初始化失败采用同一确认后释放流程。初始恢复失败不再由回滚自动重试或清除本地归属标记。
- StopMotion 失败后的同事务 StopAllBuffer 可继续尝试停止，但在 Group 仍归属当前会话时不再清表、清缓存或覆盖规划证据。
- 停止故障不会因后续 API 成功而自动消失。后续显式停止／断连仍允许在停稳确认后释放资源；完整重连成功才解除停止故障锁存。
- 断连不调用 LmtsOff。关输出、停止或关闭连接失败时保留实际连接状态，界面显示错误，不误报“全部已断开”。成功安全断连才解除队列 StopOnly 门禁，允许重新连接。
- 独立激光器停光、瞄准光、轴停止、缓冲停止和配置安全输出均尝试执行，不因其中一个失败而跳过后续安全动作；任何失败都阻止自动断连。
- 最终退出不能通过运行时析构再自动重试失败的停机。未完成安全退出时保留设备运行时、借用配置、设备队列和连接回调服务，直至进程结束；这是故障隔离，不是硬件急停保证。

原有 C 轴规划 `+360°`、反馈 `−360°` 等反馈异常保护保持不变；没有修改 CAM 符号、角度取模或放宽容差。

## 3. 日志核对

连接完成的适配器标识：`adapter_revision=confirmed-stop-and-start-guard-v10`。

重点搜索：

- `phase=stop_confirmation`：Group/List、轴掩码、实际读取状态、`read_valid`、采样次数、耗时、确认结果。无效字段不能作为真实零值解释。
- `phase=stop_release`：每个实际 SDK 调用的名称和返回码。
- `cleanup=false`、`preserve_evidence=true`：失败后的后续停机保留现场。
- `phase=configured_safe_output`：输出名、硬件标识、通道、本地／扩展、反相、逻辑 OFF 和调用是否成功；API 失败另有实际返回码。
- `handle_retained=true`、`limits_preserved=true`：停止或断连未完成，不代表控制器已经失能。
- `start_called=false`：取消发生在 SDK 启动调用之前；`start_called=true stop_pending=true` 表示启动调用返回时已有停止请求。

## 5. 现场验证边界

本轮不连接或驱动 GTN，不修改机台配置。现场应由操作人员在激光硬件禁能、低速、可触及硬件急停的条件下确认：

1. 正常连接、两轮廓空运行、停止和断连；核对 v10 标识、轴映射和规划／反馈方向。
2. 构建／封表期间停止，日志应无后续未授权启动；已进入 Start 的情况应保留事实并随后停机。
3. 列表 Delay/IO 等待时停止，确认不会继续执行后续运动或输出；重连先恢复遗留列表再加载配置。
4. 在受控台架验证状态读取失败／超时，不得报告已停稳、关闭限位或丢失连接；显式恢复后才能重连。
5. 使用实际配置的本地／扩展、反相安全输出，测量逻辑 OFF 的物理效果；不能仅以 SDK 返回零证明激光已经禁能。
