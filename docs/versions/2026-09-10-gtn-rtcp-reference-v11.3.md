# GTN RTCP 参考坐标修复 v11.3

## 问题与实施方案

用户日志 16:39:31：RTCP Group 初始化通过，首个点的 CAM 与 GTN X 轴差 63.906014 mm，B/C 一致、singularity=0。将实际世界 TCP 按 B/C 载体链逆变换后，与控制器 command_start 一致，确认不能把已随载体变换的世界 TCP 直接用作 RTCP MCS 指令点。

本批仅修复坐标契约，不修改轴方向、当量、机床配置、标定记录或非 RTCP 轴目标，不放宽一致性阈值。

1. 纯 OCC 算法：`p_reference = T_home * inverse(T_current) * p_world`，去除工件载体运动、保留工件安装变换。
2. CAM 在切割、轮廓间空程、首刀接近导出时提供独立 RTCP 参考 TCP；世界 TCP 继续服务碰撞/渲染。Process 只透传，不做 IK 或符号修补。
3. GTN 保留控制器独立变换对 CAM 轴解的校验，补充输入坐标证据并拒绝非有限值。
4. 日志实测坐标回归、转台正负角/跨圈/安装偏移、Process 透传验证；Ninja Debug 与 ASan 构建及相关软件门禁。

当前 CompDevice 未接入，XY 补偿为零。保留非 RTCP 轴补偿；未来非零补偿须经 CAM 生成相应 RTCP 参考点，不能在 Process 中直接加到 MCS XYZ，未生成时拒绝 RTCP。
