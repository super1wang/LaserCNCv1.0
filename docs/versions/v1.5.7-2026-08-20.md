# LaserCNC v1.5.7（2026-08-20）

## 交付范围

- 统一新建 CAM 图层与 Process 工具的内置 `default` 名称；旧 `Default` 自动规范化，默认工具固定排在首位且不可重命名或删除。
- 保存 CAM 自动排序方向；全局刀路生成先按当前方向排序，再执行唯一一次有序机床坐标求解、空程规划和后续碰撞校验。
- 加工预检、运行和暂停期间冻结会改变加工输入的命令、工程/CAM/机台/流程编辑和轴/I/O 操作，仅保留暂停、继续、停止及视图操作；激光加工标签页禁用机台、工件、轮廓和覆盖层选择。
- CAM 标签页增加独立“碰撞校验”按钮，可在已有刀路时无视自动碰撞检测开关发起完整校验；未加载机台模型时仍校验切割头/工件刀路，但首段跳过不存在的机台源。
- 刀路生成后清空 OCC、工程树和 SelectionService 中的轮廓选择，不再隐式选中第一个轮廓。
- 修复机台显示切换对轮廓、加工面和工作区主文档身份的影响；纯显示切换不再发布机台数据变化，也不会复制无法隐藏的加工面。
- 停止后再次开始作为新运行处理：清空断点、重新读取控制器 APOS，首轮廓不复用旧来源为 0 的过渡，并向 CAM 请求新的首段。
- Process 设置增加手动/自动首段模式、有符号绝对 Z 安全坐标和首段碰撞校验；自动兼容规划按 Z 安全候选、SafeXY、SafeAC、Approach 构造并保留 CAM 已提交首点 IK 分支。
- 新增 `ICamCollisionSafetyDomain`、碰撞几何缓存和线程安全的稀疏精确位姿证书，使刀路、空程和首段共用同一环境版本和精确碰撞结果；当前未宣称已实现完整稠密安全域。
- 控制器状态与外设轮询改用独立执行器，真实 SDK 调用继续由共享设备租约串行；长运动等待只在单次 SDK 调用期间持有租约，APOS 可持续更新。
- 为机台/工件加载、刀路生成、碰撞校验、安全域缓存、工作流、首段规划和绝对 Z 运动增加结构化阶段日志及耗时。
- 新增独立 [碰撞检测与安全域专项待办](../collision_detection_todo.md)，记录 C1/C2 稠密/分块体素场、All-AC 禁区、C3 Goal/Pose/Sweep 缓存、DDA、Theta*/A*、两层图搜索和连续碰撞等后续工作。

## 与最终设计方案的对比

- 已完成 C0 的主要运行期能力：碰撞专用 BRep、AABB/OBB、表面网格/BVH、轴绑定/变换、环境版本和后台准备；缺少持久化编译产物与完整刀具/夹具版本体系。
- 已完成可共享的稀疏精确位姿证书，但它不是 C1 `MachineAllAcSafeField`、C2 `JobSafeField` 或 C3 `GoalNavigation/AcSweepField`。
- S1 当前按正确物理 Z 方向枚举控制器绝对坐标并逐候选扫描；尚未通过 PoseField 的 DDA 获取最近安全退回域。
- S2 当前为确定性的安全 Z → SafeXY → SafeAC 顺序；尚未通过两层 A*/Theta* 选择换姿门户。
- S3 已保持首点既定 IK 分支、显式 Approach 边界和 Process 原样执行契约；尚未建立 GoalNavigationField 与完整 ApproachCorridor 证书。
- 因此本版本属于“接口、失败关闭、稀疏证书和兼容首段”的阶段性交付；稠密 All-AC 体素场和任意姿态高速图搜索明确留到下一阶段。

## 审阅结论

- 已检查全部已跟踪修改、删除项和未跟踪文件；没有发现删除文件、日志、构建产物、本地配置或与本阶段无关的辅助脚本。
- Process 继续不包含 OCC 类型；碰撞几何、精确距离和自动首段规划均由 CAM/算法层拥有，Process 只读取 APOS、提交请求并执行无 OCC 快照。
- 安全证书严格按物理轴位姿、TCP/法向、阶段、碰撞源对和间隙匹配；`Pending`/`Indeterminate` 不缓存，环境 revision 不匹配时失败关闭。
- 设备状态轮询虽与工作流队列分离，但所有控制器 SDK 入口仍获取同一 `ProcessDeviceCoordinator` 租约，没有新增并发 SDK 访问路径。
- 审阅时修复了协调运动指令汇的暂停等待边界：停止请求可立即打断暂停循环，避免“暂停后停止”令工作流线程滞留。
