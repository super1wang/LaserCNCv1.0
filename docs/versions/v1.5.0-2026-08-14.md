# v1.5.0 — CAM 驱动的离线机台仿真

日期：2026-08-14（复核完成：2026-08-17）

## 本次交付

- 新增 `simulation` 模块。它只依赖 CAM 与渲染层，不依赖 Process、控制器、激光器或串口设备。
- 新增由 CAM 持有的轮廓顺序服务。机床坐标求解、空程叠加显示、轮廓序号、Process 切割列表和仿真器均消费同一份权威 CAM 顺序；CAM 不再读取 Process 顺序。
- 新增“离线仿真”Ribbon 页面和 CAM 入口操作。进入页面时创建独立 OCC 标签页；离开时停止回放、取消扫描、移除 AIS 对象并销毁沙箱页面。
- 沙箱冻结已按顺序求解的 CAM 快照，持有私有 `MachineKinematics` 副本，支持节点定位、运行/暂停/停止、速度倍率和碰撞定位；不会写入工程、CAM 或实时机台姿态。
- 新增绿/红/灰碰撞时间线。碰撞扫描在后台执行；未完成节点保持灰色，回放在扫描完成前明确标识为“未验证”。确认发生碰撞时会高亮两个部件，并在可构造时显示 OCC 布尔交集。
- 复核修正：显式为空的碰撞源选择会被正确持久化；CAM 顺序改变时会替换进行中的完整机台校验；后台线程的工件安装变换与轴状态与冻结仿真场景保持一致。

## 验证证据

- Ninja Debug：`LaserCNC`、CAM、Process 和 simulation 目标均已链接。
- `ctest --test-dir build-cmake --build-config Debug --output-on-failure`：30/30 通过，包含启动烟测和 SDK SimulatorCMHP 集成测试。
- 静态架构检查确认 `src/modules/simulation/` 没有 Process、运动控制器、激光器、串口、ACS 或 GTN 引用，且 CAM 不再包含 `IProcessCuttingPlanProvider`。

## 仍需验证

- 代表性 AC/BC 转台与摆头模型的 GUI 交互仍需人工验证，其中包括预期允许的夹具接触组合。
- 当前碰撞源由运动学挂接关系推导；持久化的碰撞对覆盖、连续扫掠体避碰和路径重规划留待下一阶段。
- 100 次 GUI 进入/退出、ASan GUI，以及私有字节、句柄和 GPU 资源的长期趋势仍属于发布验证工作，CTest 不能替代这些验证。
