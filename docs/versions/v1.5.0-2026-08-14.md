# v1.5.0 — CAM-driven offline machine simulation

Date: 2026-08-14
Review completed: 2026-08-17

## Delivered

- Added the `simulation` module. It depends on CAM and rendering only and has
  no Process, controller, laser, or serial-device dependency.
- Added a CAM-owned contour sequence service. The machine-coordinate solve,
  travel-path overlay, contour labels, Process cutting list, and simulator now
  consume one authoritative CAM sequence; CAM no longer reads Process order.
- Added the Offline simulation Ribbon page and a CAM entry action. Selecting
  the page creates a separate OCC tab, while leaving it stops playback,
  cancels scanning, removes AIS objects, and destroys the sandbox page.
- The sandbox freezes the ordered solved CAM snapshot, owns a private
  `MachineKinematics` copy, supports node seek, run/pause/stop, speed factors,
  collision navigation, and does not write project, CAM, or live machine pose
  state.
- Added a green/red/gray collision timeline. Collision scanning runs in the
  background; pending nodes stay gray and playback is explicitly marked
  unverified until it finishes. A confirmed active collision highlights both
  bodies and displays an OCC boolean intersection whenever it can be built.
- Review corrections preserve explicitly empty collision-source selections,
  replace an in-flight full-machine verification when the CAM order changes,
  and keep worker-thread workpiece setup/axis state identical to the frozen
  simulation scene.

## Verification

- Ninja Debug: `LaserCNC`, CAM, Process, and simulation targets linked.
- `ctest --test-dir build-cmake --build-config Debug --output-on-failure`:
  30/30 passed, including the startup smoke and SDK simulator integration
  tests.
- Static architecture checks confirm `src/modules/simulation/` has no Process,
  motion-controller, laser, serial, ACS, or GTN reference, and CAM no longer
  includes `IProcessCuttingPlanProvider`.

## Remaining validation

- GUI interaction with representative AC/BC-table and head-model fixtures,
  including intended fixture-contact ignore pairs, remains manual validation.
- The current collision role configuration is inferred from kinematic
  attachments; persisted pair-level overrides, continuous swept-volume
  avoidance, and path re-planning are reserved for the next collision and path
  optimization phase.
- 100-cycle GUI enter/exit, ASan GUI, and long-running private-byte/handle/GPU
  trend gates remain release validation work and are not replaced by CTest.
